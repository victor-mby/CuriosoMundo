2. ESQUEMA SQL (base_datos.sql)
===============================================================================

PRAGMA journal_mode = WAL;

-- Catalogo de estaciones
CREATE TABLE IF NOT EXISTS estaciones (
    id TEXT PRIMARY KEY,
    nombre TEXT NOT NULL,
    linea TEXT,
    zona TEXT,
    operador TEXT
);

-- Catalogo de motores / equipos de bombeo
CREATE TABLE IF NOT EXISTS motores (
    id TEXT PRIMARY KEY,
    estacion_id TEXT NOT NULL,
    descripcion TEXT,
    hp REAL,
    voltaje_nominal REAL,
    etapas INTEGER,
    eficiencia REAL,
    factor_potencia_nominal REAL,
    altura_cierre REAL,
    caudal_diseno REAL,
    FOREIGN KEY (estacion_id) REFERENCES estaciones(id)
);

-- Tabla principal de telemetria (29 campos)
CREATE TABLE IF NOT EXISTS registros_telemetria (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    tiempo REAL NOT NULL,
    tiempo_simulacion TEXT,
    timestamp INTEGER NOT NULL,
    fecha TEXT,
    hora TEXT,
    motor_id TEXT NOT NULL,
    nivel REAL NOT NULL,
    nivel_porcentaje REAL NOT NULL,
    voltaje REAL NOT NULL,
    voltaje_terminal REAL NOT NULL,
    amperaje REAL NOT NULL,
    corriente_nominal REAL NOT NULL,
    caudal REAL NOT NULL,
    potencia REAL NOT NULL,
    potencia_nominal REAL NOT NULL,
    carga REAL NOT NULL,
    altura REAL NOT NULL,
    factor_potencia REAL NOT NULL,
    estado_motor TEXT NOT NULL,
    estado_valvula TEXT NOT NULL,
    posicion_valvula REAL NOT NULL,
    velocidad_rotacion REAL NOT NULL,
    horas_operacion REAL NOT NULL,
    caudal_total REAL NOT NULL,
    potencia_total REAL NOT NULL,
    corriente_total REAL NOT NULL,
    nivel_destino REAL NOT NULL,
    demanda REAL NOT NULL,
    nivel_tanque_maximo REAL NOT NULL,
    FOREIGN KEY (motor_id) REFERENCES motores(id)
);

-- Registro de eventos del simulador (incluye alarmas como eventos)
CREATE TABLE IF NOT EXISTS eventos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    tiempo REAL NOT NULL,
    hora TEXT NOT NULL,
    tipo TEXT NOT NULL,
    equipo TEXT NOT NULL,
    severidad TEXT DEFAULT 'INFO',
    texto TEXT NOT NULL,
    estado TEXT DEFAULT ''
);

-- Alarmas stateful (capturadas desde el gestor de alarmas)
CREATE TABLE IF NOT EXISTS alarmas (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    tiempo_activacion REAL NOT NULL,
    tiempo_desactivacion REAL,
    id_regla TEXT NOT NULL,
    titulo TEXT NOT NULL,
    severidad TEXT DEFAULT 'MEDIA',
    equipo TEXT NOT NULL,
    mensaje TEXT NOT NULL,
    valor REAL,
    limite REAL,
    veces INTEGER DEFAULT 1,
    acknowledge INTEGER DEFAULT 0
);

-- Indices para rendimiento en consultas ML
CREATE INDEX IF NOT EXISTS idx_telemetria_motor_tiempo ON registros_telemetria(motor_id, tiempo);
CREATE INDEX IF NOT EXISTS idx_telemetria_tiempo ON registros_telemetria(tiempo);
CREATE INDEX IF NOT EXISTS idx_eventos_tiempo ON eventos(tiempo);
CREATE INDEX IF NOT EXISTS idx_eventos_tipo ON eventos(tipo);

3. VISTA SQL PARA MACHINE LEARNING (view_ml.sql)
===============================================================================

CREATE VIEW IF NOT EXISTS vista_telemetria_ml AS
SELECT
    id,
    tiempo,
    timestamp,
    fecha,
    hora,
    motor_id,
    nivel,
    nivel_porcentaje,
    voltaje,
    voltaje_terminal,
    amperaje,
    caudal,
    potencia,
    carga,
    altura,
    factor_potencia,
    caudal_total,
    potencia_total,
    corriente_total,
    nivel_destino,
    demanda,
    estado_motor,
    estado_valvula,
    posicion_valvula,
    velocidad_rotacion,
    horas_operacion
FROM registros_telemetria
ORDER BY motor_id, tiempo;

-- Variables objetivo para el modelo:
-- - Hidraulicas: nivel, caudal, altura, nivel_destino, demanda
-- - Electricas: voltaje, voltaje_terminal, amperaje, corriente_total, factor_potencia
-- - Operacion: carga, potencia, caudal_total, potencia_total
-- - Estado: estado_motor, estado_valvula (requieren codificacion en Python)
-- - Complementarias: posicion_valvula, velocidad_rotacion, horas_operacion
--
-- NO incluir en entrenamiento automatico sin procesamiento:
-- - motor_id: identificador categorico
-- - tiempo, timestamp, fecha, hora: indices temporales
-- - potencia_nominal, corriente_nominal, nivel_tanque_maximo: constantes

6. HALLAZGO IMPORTANTE SOBRE EL SIMULADOR
===============================================================================

El simulador genera 29 campos por registro en la funcion capturar()
(simulador/src/simulacion/simulador.js, lineas 68-100).

Sin embargo, la funcion de exportacion CSV (simulador/src/simulacion/historial.js)
solo incluye 16 columnas (definidas en COLUMNAS, lineas 108-125).

Columnas presentes en el simulador pero AUSENTES en el CSV exportado:
    1.  timestamp
    2.  voltaje_terminal
    3.  corriente_nominal
    4.  potencia_nominal
    5.  carga
    6.  altura
    7.  factor_potencia
    8.  posicion_valvula
    9.  velocidad_rotacion
    10. horas_operacion
    11. corriente_total
    12. nivel_tanque_maximo

El schema SQLite y la VIEW estan disenados para almacenar TODOS los campos
que el simulador genera. Al importar el CSV, las columnas ausentes quedan
como NULL en la base de datos.

IMPORTANTE: El simulador NO fue modificado. Si se requiere obtener los 12
campos faltantes para el modelo, se necesitara autorizacion explicita para
modificar el exportador del simulador o crear un mecanismo alternativo
de captura.

9. ETAPA 2 - COMPONENTES CREADOS
===============================================================================

9.1 ml/preparar_datos.py
    - Funcion: preparar() -> dict
    - Descripcion: Carga datos desde la VIEW, selecciona variables ML,
      limpia nulos/infinitos, normaliza con StandardScaler y retorna
      X (numpy), scaler, columnas, df_raw, df_clean.
    - Uso: python ml/preparar_datos.py

9.2 ml/autoencoder.py
    - Clase: Autoencoder(nn.Module)
    - Arquitectura:
        Entrada -> Dense(input_dim, max(bottleneck*2, input_dim//2)) -> ReLU
                -> Dense(..., bottleneck_dim) -> ReLU
                -> Dense(bottleneck_dim, max(bottleneck*2, input_dim//2)) -> ReLU
                -> Dense(..., input_dim)
    - Funcion: entrenar_autoencoder(X, epochs=50, batch_size=64, lr=1e-3)
    - Funcion: calcular_error_reconstruccion(modelo, X) -> errores MSE por muestra
    - Dependencia: PyTorch 2.14.0

9.3 ml/entrenar_modelo.py
    - Funcion: main()
    - Descripcion: Orquesta preparacion, entrenamiento, calculo de error,
      umbral, deteccion y guardado del modelo.
    - Uso: python ml/entrenar_modelo.py

9.4 ml/detectar_anomalias.py
    - Funcion: calcular_umbral(errores, percentil=95)
    - Funcion: detectar(df_raw, errores, umbral) -> df con columnas
                error_reconstruccion, umbral, anomalia
    - Metodo umbral: percentil 95 del error de reconstruccion

9.5 ml/guardar_modelo.py
    - Funcion: guardar(modelo, scaler, columnas, umbral, ruta)
    - Guarda:
        ml/modelos/autoencoder.pth
        ml/modelos/columnas.json
        ml/modelos/umbral.txt
        ml/modelos/scaler.json

9.6 ml/modelos/ (directorio creado automaticamente)
    - autoencoder.pth  # pesos del modelo entrenado

    - umbral.txt       # valor del umbral calculado

10. ETAPA 2 - ARQUITECTURA Y METODOLOGIA
===============================================================================

Variables utilizadas (18):
    - nivel
    - nivel_porcentaje
    - voltaje
    - voltaje_terminal
    - amperaje
    - caudal
    - potencia
    - carga
    - altura
    - factor_potencia
    - caudal_total
    - potencia_total
    - corriente_total
    - nivel_destino
    - demanda
    - posicion_valvula
    - velocidad_rotacion
    - horas_operacion

Normalizacion: StandardScaler (media 0, desviacion 1)

Arquitectura Autoencoder:
    - input_dim = 18
    - bottleneck_dim = 6
    - Encoder: Linear(18, 9) -> ReLU -> Linear(9, 6) -> ReLU
    - Decoder: Linear(6, 9) -> ReLU -> Linear(9, 18)

Entrenamiento:
    - epochs: 50
    - batch_size: 64
    - learning_rate: 1e-3
    - optimizer: Adam
    - loss: MSE

Calculo del error: MSE por muestra (error medio de reconstruccion)

Umbral: Percentil 95 del error de reconstruccion

Deteccion:
    - error <= umbral -> comportamiento normal (0)
    - error > umbral  -> posible anomalia (1)

Sin etiquetas artificiales. El modelo aprende por reconstruccion.
