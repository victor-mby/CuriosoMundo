    - Loss: MSE
    - batch_size: 64
    - epochs: 50

Metodo de normalizacion: StandardScaler

Metodo de umbral: Percentil 95 del error de reconstruccion MSE

Metodo de deteccion:
    - error <= umbral -> comportamiento normal (0)
    - error > umbral  -> posible anomalia (1)

Sin etiquetas artificiales. El modelo aprende por reconstruccion.

Reglas de interpretacion:
    1. Posible comportamiento electrico anormal
       - Variables: voltaje, voltaje_terminal, amperaje, corriente_total,
                    factor_potencia, potencia
       - Descripcion: Revisar alimentacion electrica, corriente, tension
                      y factor de potencia.

    2. Posible comportamiento hidraulico anormal
       - Variables: caudal, altura, nivel, nivel_destino, demanda
       - Descripcion: Revisar caudal, niveles, demanda y condiciones
                      de impulsion.

    3. Posible sobrecarga del sistema
       - Variables: carga, amperaje, potencia, corriente_total
       - Descripcion: Revisar corriente, potencia y carga del motor.

    4. Posible restriccion o condicion anormal del flujo
       - Variables: caudal, posicion_valvula, altura, demanda
       - Descripcion: Revisar valvula, caudal y condiciones hidraulicas.

    5. Comportamiento operativo fuera del patron normal
       - Variables: todas las desviadas
       - Descripcion: Se detectaron desviaciones multiples. Requiere
                      inspeccion.

Metodo de severidad:
    - error <= umbral -> NORMAL
    - umbral < error <= 1.5 x umbral -> ATENCION
    - error > 1.5 x umbral -> CRITICO

7. HALLAZGOS Y CORRECCIONES DE INTEGRACION
===============================================================================

Problema 1: Columna 'id' faltante en inferencia
    - Causa: inferir.py solo retornaba variables ML, sin columnas
             de identificacion
    - Impacto: Dashboard no podia mostrar motor_id, fecha, hora
    - Correccion: inferir.py ahora preserva id, motor_id, tiempo,
                  fecha, hora
    - Archivo corregido: ml/inferir.py

Problema 2: Importaciones del dashboard
    - Causa: Importaciones relativas fallaban al ejecutar app.py
             directamente
    - Impacto: Dashboard no se iniciaba
    - Correccion: Uso de importaciones absolutas en
                  dashboard/servicios/dashboard.py y ajuste de
                  sys.path en pruebas/probar_etapa3.py
    - Archivos corregidos:
        * dashboard/servicios/dashboard.py
        * pruebas/probar_etapa3.py

Problema 3: Inconsistencia de umbral entre etapas
    - Causa: Cada ejecucion de Etapa 2 reentrena y sobrescribe
             umbral.txt
    - Impacto: Etapa 3 cargaba umbral de ejecucion anterior
    - Estado: Ahora consistente. Ultimo umbral: 0.372668
    - Nota: El valor varia segun la ejecucion por aleatoriedad
            del entrenamiento
